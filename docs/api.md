# Second Cursor client contract

The macOS app is the runtime. MCP over HTTP (`/mcp`), JSON over HTTP (`/api`), the native stdio proxy (`SecondCursor mcp`), and the JavaScript SDK all reach the same tool dispatcher and the same policies. No provider credentials are stored in the runtime. A local development signature and a Developer ID notarized release are different distribution modes; see [release packaging](release-distribution.md).

## Connections

Read the localhost port and bearer token from `~/Library/Application Support/SecondCursor/config.json` (or `$SC_HOME/config.json` when `SC_HOME` is set). POST `/api` with `Authorization: Bearer …`, `Content-Type: application/json`, and a body such as:

```json
{"tool":"session","args":{"action":"create"}}
```

The response uses MCP's content envelope: text items contain result JSON and image items contain base64 PNG data. `isError` distinguishes refused or failed operations. `{"tool":"tools/list"}` returns the tool definitions. MCP clients use `/mcp`: `initialize` returns a `Mcp-Session-Id` header for a separate runtime session, and subsequent requests must send that header. A missing header receives HTTP 400; an unknown or closed session receives HTTP 404. Reinitializing with a valid header reconnects to that session, and `DELETE /mcp` closes only that session. The native and Node stdio proxies manage this header for the host.

Hosts that only launch commands run `~/Applications/SecondCursor.app/Contents/MacOS/SecondCursor mcp`, which proxies stdio to the running app and starts it if needed. `SecondCursor install-mcp --client cursor|claude|codex|gemini` writes that entry for you; `SecondCursor doctor` checks the setup. Transport sessions can reconnect after an app restart while their persisted identity remains valid: 24 hours of idle retention, or `operationRetentionSeconds + 300` when that is longer. Reconnection does not restore app approvals, target claims, or permission to continue an interrupted task.

## Observations

`get_window_state` returns `snapshot_id` and a compact outline. The first read of a window in a session is the whole outline; later reads return only changed lines (`is_diff: true`, `diff_base`). Diffs compare content, not position: when a scroll or resize only moves elements, they are summarized in one line (`~ N elements moved (scroll or resize)…`) instead of being resent; `full: true` returns every current frame. Outlines stop at `max_elements` indexed elements (default 400, 50–3000; the value sticks for that window until the turn ends), and a truncated outline ends with a line naming the containers it left out. `scope` takes an element index or a container label such as `"Clip Detail"` and reads that part at full depth. Indexed lines show window-local frames, unusual states only (`enabled=false`, `focused=true`, `selected=true`, `expanded=true`), and `actions=[…]` only for actions beyond the obvious press/confirm/menu. Full outlines end with `focused: [i] Role "label"` and, when text is selected, `selected text: "…"`; both take part in diffs. `scope` reads one subtree at full depth. `inspect_element` recovers full values and selection ranges in UTF-16 units. `structured: true` adds the `elements` JSON array to full and scoped reads; diffs never include it.

Screenshots are opt-in (`include_screenshot`) and at most 1024 px on the long edge, because clients shrink larger images and the model would otherwise read positions off a scaled copy. Each screenshot reports `scale` (image pixels per window point) and a `coordinates` hint. Pixel tools take window points by default; pass `coordinate_space: "screenshot"` to use pixels from the latest screenshot of that window instead. A screenshot taken soon after an action allows time for the app to repaint. Native screenshot `freshness` is explicitly `unverified`: `captured_at` records capture time, and `changed_since_previous_capture` reports pixel differences, but neither proves the app repainted or the action succeeded. Off-Space custom surfaces may stop repainting. If capture fails, the outline still comes back, with `screenshot_error`.

Every native action (`click`, `drag`, `type_text`, `set_value`, `press_key`, `scroll`, `perform_action`, `select_text`, `paste`) returns an `observation`: the diff against the session's previous read of that window, taken after the UI settles. It advances the diff baseline and becomes the window's current observation. `observe` chooses `tree` (default), `both` (adds a screenshot), `screenshot`, or `none` (no read, no settle wait; use it when chaining blind steps). The settle wait follows the app's accessibility notifications: it waits up to 250 ms for the first notification after the action, then for 60 ms without one, capped at 3 s; apps that post nothing fall back to polling for 200 ms of quiet. `press_key` reports `verified: true` when the app confirmed the menu press was delivered; that doesn't prove the command had an effect, so check the observation. A failed read after a successful action is reported as `observation_error`, not as a failure. `batch` returns one observation after its last step.

Browser actions (`browser_click`, `browser_type`, `browser_press_key`, `browser_scroll`, `browser_navigate`) do the same for their tab: after the page settles they return an `observation` like `browser_snapshot`'s, the removed (`-`) and added (`+`) outline lines since the session's previous read of that tab, or the whole outline when that is not much smaller, and take `observe`. `browser_snapshot` defaults to `full: false`, so only the first read of a tab (or `browser_open`) returns the whole outline; pass `full: true` for the whole outline again. A click by ref (`browser_click`) or locator (`browser_command` `click`, also in a `batch`) first checks, as Playwright does, that the element itself is what a click at its center would hit; layers with `pointer-events: none`, the agent's cursor among them, do not count. While something else covers it (a toast, a banner, a dialog backdrop), the check repeats for up to 2 s, then the click is refused without being sent, and the error names what covers the element. Clicks at `x`/`y` are sent where asked. A page with an open JavaScript dialog cannot be read: the action that opened it reports `observation_error`, and `browser_snapshot` is refused, until `browser_command` `operation: dialog` answers it.

Browser snapshots include `freshness: {revision, captured_at_ms, age_ms, status}`; `status` is `current` or `changed_during_capture`. With an explicit `observation_id`, a mutation refuses superseded snapshots or detected DOM, form-property, viewport, or frame changes before dispatch. Raw pixel actions recheck after cursor animation. Without an explicit ID, ref and locator actions resolve and hit-test the live target again, which supports predictable batches. These guards cover open shadow roots but exclude closed roots, canvas/video repainting, and layout changes without DOM or viewport events, such as CSS hover states or an image resolving its intrinsic size. A raw pixel token is a DOM/viewport guard, not a pixel hash. Checkbox and radio `change` events count as a reaction during settling; ordinary text-input events do not shorten the wait for a debounced search.

Window tools take `window_id` or `app` (name or bundle id). For reads and screenshots, `app` means that app's only window, or the main window of its frontmost process; when it can't choose, the error lists candidate window ids. Actions, `inspect_element`, and scoped reads by `app` go to the app window this session observed last, so indexes and coordinates always refer to the window you saw; they are refused if you haven't observed one or it has closed. Results carry the resolved `window_id`. Codex-style argument names are accepted: `click_count`, `mouse_button`, `key` (xdotool names such as `Return`, `Page_Up`, `KP_Enter`, `super+c`; `browser_press_key` and tab batch steps take `key` too), and `pages` for scrolling. A window tool called with neither `window_id` nor `app` by a session whose latest target is an agent tab is refused with that tab's id and a pointer to `browser_snapshot` and the browser tools. An argument refusal before any input is sent carries no `operation_id` to reconcile.

`browser_snapshot` adds a `hint` when the page is unchanged since the observation the session last received of that tab with no input since: it names the action whose result already had the page, or the read it repeats, and the `browser_command` `operation: wait` call (with `locator` text and `state: attached`) that waits for a change in one call instead of polling. From the third unchanged read in a row, a `full: true` read of a whole outline the session got in the last 30 s answers `(no changes)` with `is_diff: true` and `diff_base` naming that read, instead of resending it; `structured: true` reads, reads after a `browser_repl` call, after input without an observation, or after the turn ended are always whole. `browser_screenshot` adds one saying text is read from the outline. A tab id that is not, or no longer is, an agent tab is refused with a pointer to `browser_open`.

Pass `observation_id` when acting on a previous observation; a superseded one is rejected. Native indexed actions recheck the element's liveness, role, and name, and a newly exposed sheet requires a fresh read. Pointer coordinates are checked against the observed window size and a bounded accessibility fingerprint of topology, geometry, and noneditable content, so same-size reflows can also invalidate coordinates. The fingerprint covers at most 2,500 AX nodes and cannot detect changes confined to custom-drawn pixels. Editable values, focus, and selection do not globally invalidate every index. `stop_on_layout_change: false` deliberately opts a native batch out of the coordinate layout guard; it does not bypass observation-ID, human-input, or pause checks. Read `get_window_state` at the start of each turn before acting.

## Native capabilities and human input

`capabilities` returns the native backend's supported gestures, reasons for current restrictions, and suggested alternatives; pass `window_id` for target-specific restrictions. `status.native_capabilities` exposes the general profile, including `input_monitoring_available`. Unsupported native modifier clicks, modifier drags, and hover are refused before input. Required private macOS input symbols or key-window targeting failures also refuse rather than silently switching to a weaker route.

The passive input monitor gives the human priority. A mutation is refused while observed human input to that app is less than two seconds old. Input after an observation invalidates it even once the quiet interval passes, so read again after the user yields. If monitoring is unavailable, foreground mutations are refused conservatively; background work remains available. Pointer and keyboard input into a different key window of the human's foreground app is refused because it could redirect their typing; a semantic AX action may still be available. Dispatch checkpoints repeat these checks, including between batch and input steps, and release pressed keys or buttons when interrupted.

The agent display shares the current GUI session, app processes, and clipboard. It can move work out of view, but cannot supply isolation or prove that a custom surface is repainting. Use an exposed semantic action or an owned browser tab when the native capability profile suggests it. Work that needs a separate GUI session requires a separately configured environment; Second Cursor does not provision or silently switch to a VM.

If `launch_app` with `on_agent_display` opens an unreachable window on a desktop the user is not viewing, it reports the failed placement and leaves the window in place. No delayed move is queued. Observe the window again and issue a new `move_to_agent_display` request when it becomes reachable. `agent_display` with `action: teardown` refuses while any native input is in flight or another session holds a native window claim. Once admitted, it excludes new native claims and input until the display operation finishes, including requests from the same task.

## Postconditions and waiting

Native actions and `batch` take `expect`, so an action can verify its own outcome instead of reading the window again: `{text}` (some element's title, value or description contains it, case-sensitive) or `{element_index, value}` (that element's value equals it exactly), plus `gone` (wait for the condition to stop holding) and `timeout_ms` (default 2000, at most 10000). The condition is checked once before the action and waited for after it (after the last step of a `batch`), waking on the app's accessibility notifications and re-checking every 250 ms for apps that post none. The result adds `expect: {status, waited_ms, detail}`: `verified`, `preexisting` (it already held before the action, so the end state is right but the action is not proven to have caused it), or `failed`. A failed postcondition is not an error: the observation, taken after the wait, still comes back, and `detail` says what was last seen. Malformed `expect` is refused before anything is sent; it may also arrive as a JSON string.

`browser_click`, `browser_type`, `browser_press_key`, `browser_scroll`, and `batch` with `tab_id` also take `expect`. Use `{text: "Saved receipt 42", timeout_ms: 5000}` for case-sensitive text in the public accessibility content, or `{ref: "e12", value: "Approved"}` for an exact, untruncated public field value. Supplying both checks requires both to hold; `gone: true` negates the combined condition. A ref stays bound to its original node and document; a replacement control with the same value cannot satisfy it. Text checks stay in the original tab across navigation and never follow another tab. Hidden text, document titles, overlays and protected values do not establish success; incomplete frame or privacy coverage cannot prove absence.

Browser expectations accept an object or JSON string. Unknown fields, invalid combinations, and non-integer or out-of-range `timeout_ms` values are refused before input; the range is 0–10000 with a 2000 ms default. The result contains `expect: {status, reason, waited_ms, detail}` with the same `verified`, `preexisting` and `failed` distinctions. `observe: "none"` still waits for the requested condition; it only omits the final observation. A failed check leaves the action's outcome uncertain because input may already have taken effect, and no action is repeated automatically. Inspect the current result before retrying. Polling, in-flight reads and the optional final observation are bounded separately; the host's overall call deadline remains authoritative.

A tab batch checks once before its first step and waits after its final successful step. Any failed, skipped or uncertain step prevents verification, even if a matching status is visible. A JavaScript dialog interrupts the check and remains available for explicit handling. Unsupported browser routes, including `browser_navigate`, `browser_command` and `browser_repl`, reject `expect` rather than ignore it. The selected extension must advertise `browser_expect_v1`; an older loaded extension is refused before dispatch and must be reloaded after installation. These checks establish an observed UI condition, not independent proof of a server commit; use application receipts or persisted-state checks when the task requires them.

Mutating results also include `outcome: {state, verified, reason}`. `dispatched` means input was sent without an outcome check; `observed` means a resulting observation is available; `verified` means the operation's explicit postcondition was checked; `uncertain` means delivery may have happened but its resulting state could not be established; `failed` means a postcondition or batch step failed. Native `expect` establishes verification only when the condition changed from false to true. Read `outcome.verified` for outcome evidence: older top-level delivery acknowledgements such as `verified` on `press_key` do not prove the requested effect. A screenshot, a successful transport response, and a preexisting native postcondition are not a verified result. Inspect the current state before retrying an uncertain or partly failed action.

A native AX action the app cannot confirm can still execute later. Its result carries machine-readable `uncertain: true`, and the default `stop_on_error: true` stops the remaining native batch steps on that uncertainty. A following observation does not convert the acknowledgement into success; an explicit verified postcondition is needed to establish the requested result. Reobserve before retrying rather than dispatching a second copy of the action.

`wait_for` waits for the same condition without acting: `{window_id | app, text?, element_index?, value?, gone?, timeout_ms?}`. It returns the status (a condition that already holds is `verified` with `waited_ms: 0`) and the window's observation diff. It is a read, never holds the app's queue between checks, and keeps presence alive like other reads.

## Text recognition

`get_window_state` with `ocr: true` also reads the text drawn in the window, for apps that draw text accessibility does not expose (DAWs, games, canvases). Recognition runs on device with Apple's Vision framework, on a full-resolution capture of the window rather than the 1024 px screenshot. Recognized text that repeats the label, value or title of an element it overlaps is left out, even with a stray glyph attached, such as the chevron beside a document title. Text inside an indexed element goes on that element's line as `ocr="…"` (several joined with ` | `). Other text becomes a line without an index under the deepest container holding it, such as `text "Export" (412,88 40x14)`, framed in window points; it is not an accessibility element, so click it with x/y at its center. Results add `ocr_ms` (capture and recognition) and `ocr_count` (texts merged); if recognition fails, the outline still comes back, with `ocr_error`. With `scope`, only text inside that element is kept. Recognized text only takes part in diffs between `ocr` reads: a read without `ocr` compares plain outlines, so it never reports recognized lines as removed, and an `ocr` read compares against the previous outline with the last recognized text merged in. On an M2 Pro a read with `ocr` costs about 0.2 s for a small window and 0.3–0.6 s for a 1300×850 pt one. The first recognition on a Mac, and again after an OS update, waits while Vision compiles its model for the Neural Engine, which takes a minute or more; such a read gives up on text after 15 s and returns `ocr_error`, and the compile finishes in the background while the app keeps running.

## Sessions, ownership, and retries

An initialized MCP connection uses its own runtime session automatically, so ordinary clients receive separate observation histories, approvals, and native target leases. Custom `/api` hosts should create a session and pass `session_id` on subsequent tools; omitting it there retains the shared `legacy` compatibility behavior. A valid explicit `session_id` can select a task session through an authenticated MCP connection, but cannot select `legacy`. The local bearer token grants access to the runtime; these opaque IDs scope ownership, not authentication between hostile clients.

Native reads are permitted across sessions. Non-legacy actions hold an idle lease on the window; legacy actions respect existing leases but never take one. Leases expire after five idle minutes (`claimIdleSeconds`), and in-flight actions keep theirs. `bind_target` claims or releases `window:<id>`. Closing a session cancels queued work, releases targets and approvals, closes temporary agent-created tabs, and releases claimed personal tabs without closing them.

Supply an `operation_id` before submitting an action and reuse it only for an identical request; the server returns the retained outcome instead of running it again, and refuses a different request using the same ID. Mutations without an ID receive a generated `operation_id` in their result and retain bounded outcome metadata, but not their response body. Explicit IDs can also retain response bodies in memory until expiry or eviction. `operation_status` reconciles timeouts and `cancel_operation` stops queued work, but neither can undo input already delivered. `timeout_ms` includes approval and queue time and is capped at 60000. Recovery is bounded by `operationRetentionSeconds` (one hour by default), so an expired operation ID is not a permanent deduplication key. `status.runtime` reports retained operations, result bytes, and open HTTP connections.

The `task`, `session`, and `bind_target` control APIs bypass the operation journal. Recover a lost control response by inspecting task state, validating the session, or reading target ownership; `operation_status` cannot reconcile those controls.

The private `operation-journal` directory under the runtime's support directory persists request signatures and execution metadata before dispatch. It contains SHA-256 signatures and outcome metadata, not arguments, screenshots, or response bodies; the directory uses mode 0700 and its files 0600. After restart, a recorded intent that never reached dispatch becomes `interrupted` with `outcome_known: true`; an operation that reached dispatch without a terminal record becomes `uncertain` with `outcome_known: false`. Terminal outcome metadata survives, but recovered operations have `result_expired: true` because response bodies are not persisted. An identical retry returns this metadata and does not repeat the action. Observe the target before deciding whether to submit a new operation. If the journal cannot be read or written, mutations are refused before dispatch while read-only diagnosis remains available.

Native batches cannot cross app processes. Browser batches cannot cross tabs. Both run in order and recheck admission between steps. A native step is the tool name plus that tool's arguments, `{"tool": "click", "element_index": 5}`; the older `{"tool": "click", "args": {...}}` still works, with `args` as an object or a JSON string. `browser_command`'s `arguments` may also be a JSON string. Both allowances exist because Gemini through Cursor stringifies free-form nested objects and garbles the keys of declared ones. A malformed `args` or `arguments` is refused with an error naming the field, and a step missing a required argument lists any fields it did not recognize.

Native batches also accept `select_text` with `element_index`, exact `text`, optional `prefix`/`suffix`, and `selection_type` (`text`, `cursor_before`, or `cursor_after`). Selection and insertion use the same guarded paths as standalone calls. The whole batch is parsed before any step runs; an ambiguous or missing text match stops the following steps by default, and an unconfirmed selection reports uncertainty rather than allowing typing at an assumed caret. Put a final `expect` on the batch to verify the resulting document in the same call.

## Tasks and human takeover

Each session gets a task when it starts working with a target or explicitly calls the task API. Use `task` with `action: create` and a short `title` to name unused work, `get` or `list` to inspect it, and `update` to report progress. `list` returns only tasks associated with the calling session, excluding finished tasks unless `include_finished: true`; the native panel shows all clients. `task_id` defaults to the session's current task, and an explicit ID cannot control another session's active task. Responses contain `{task: ...}` or `{tasks: [...]}` with snake_case snapshot fields such as `in_flight_count`, `requires_fresh_observation`, and `last_verified_outcome`.

Hosts can report `queued`, `running`, `thinking`, `needs_user`, `completed`, or `failed`; controls add `paused`, `cancelled`, and `interrupted`. Supply `client_name` to identify the host. Task state does not expire when the model goes quiet: finishing a tool call can leave the task thinking, but only an explicit lifecycle update finishes it. A reported completion is not outcome verification.

`pause`, `takeover`, and `cancel` stop new mutations for that task, including later batch steps. Already dispatched input may still finish, and the task reports its in-flight count while it drains. Takeover releases target claims after that boundary so the human can work. `resume` is refused until in-flight input has drained, never activates an app, and requires a fresh observation of each target before the next mutation. Reads made during takeover do not satisfy that requirement. An ordinary `update` cannot bypass a paused task or one awaiting the user. Cancellation cannot undo input that was already sent.

Open **Tasks…** from the menu bar or run `SecondCursor --show-tasks` to see the same registry. Each task shows its state, client, target app/window or tab, and last result verified by the runtime. The panel provides per-task Pause, Take over, Resume task, and Cancel task controls. **Show app** deliberately activates the running app named by that target's bundle ID; it does not promise to reveal an exact window, launch the app, or resume the task. Global pause remains a separate control.

The registry saves task metadata in `tasks.json` in the runtime support directory. Nonterminal tasks become `interrupted` after restart. Use `task` with `action: bind` and `task_id` to associate a live session with that interrupted task before resuming; active tasks cannot be rebound. A session still bound to its interrupted task (a transport session reconnecting after the restart) is refused input until `resume`, except `browser_open`, which resumes the task as `resume` would and says so in `resumed_task`: it opens a new tab, sends no input to an earlier target, and earlier targets still need a fresh read. A pause, takeover or cancellation still refuses `browser_open`. Refusals before a call starts carry no `operation_id` to reconcile. Persisted labels and targets do not restore app approvals or target ownership. Keep task titles and client labels free of sensitive content; captured UI and raw tool arguments are not part of this task history.

## Approvals

The agent needs the user's approval to read or operate an app. The first window tool or `launch_app` call for an app shows a local prompt: **Allow for this session**, **Always allow** (saved to `approvedBundleIDs`), or **Deny**. Concurrent calls for the same app share one prompt. Session approvals last until the session closes; for the `legacy` session, until the turn ends or the app quits. `appApproval: "off"` in the config turns this off. Blocked apps (`blockedBundleIDs`) are never reachable.

Sensitive browser operations always ask, once per call: `user_tabs`, `claim`, `history`, `clipboard`, `cdp`, and `upload` (which hands local files to a web page). A claim lasts until the tab is released, the session or turn ends, or the tab sits idle for five minutes. `confirmationRequiredTools` lists extra tools that always ask. Listing a browser tool also covers the tab `batch` and `act` steps and the `browser_command` operations that do the same work, and every `browser_repl` call, since a script can do it too. `browser_click` covers `click`, `check`, `perform_action`, `select_option`, `drag` and `dialog`. `browser_type` covers `type`, `fill` and `paste`. `browser_snapshot` covers `dom_snapshot`, `inspect` and `query`. Prompts name the app, site, and every full file path involved, expire with the call deadline, close on cancellation, and intentionally take focus. The model cannot approve itself; the extension checks the grant again on its side.

`approvals` in the config decides how every prompt is answered: `prompt` (default), `deny` (refuse without UI), or `allow` (grant without UI, including sensitive browser operations and `confirmationRequiredTools`). Blocked apps stay blocked under `allow`. The setting is read at launch.

Approvals limit what an agent can do through Second Cursor's tools. They are not a sandbox: an agent that can also run shell commands as you can edit the config, or start its own instance with `SC_HOME`, and that instance inherits the app's Accessibility and Screen Recording permissions. If an agent has unrestricted shell access, treat approvals as a guard against mistakes, not against a determined agent.

## Agent presence

While an agent works, its cursor (a black arrowhead with a white outline and an orange glow) stays on screen at its last position, and the menu bar indicates its task state. The cursor springs to each pointer action, or travels an arc on long moves, and the input is sent once it lands, as in Codex: about 0.2 s for a short move, at most 0.5 s for a long one, never more than 1.5 s. The cursor belongs to its window: it sits directly above the target app's frontmost window under its point (so the app's own menus and sheets stay beneath it), shows wherever you can see that window, and hides while another window covers the point or the window is on another Space. The agent keeps working either way. Only a cursor you can see is waited for, so actions on covered windows, windows on another Space, and background tabs go at once, and a hidden cursor jumps to its new point so it is in place when the window comes back into view. At rest it breathes and wobbles every few seconds so a running task looks alive; with Reduce Motion it stays still. Reads, keyboard actions, pointer actions, and browser calls keep cursor presence alive. The cursor clears at turn end, session close, pause, or after 60 s without calls; this does not finish the task. The menu bar uses the task registry to show working, thinking, paused, or needs-you state even while the cursor is hidden. `status.agent_activity` reports the recent cursor activity as `{active, app, sessions, arrow, arrow_visible, caption, idle_seconds}`; use the task API for durable lifecycle state.

Action tools take an optional `caption`: a few words shown in a pill beside the cursor, such as "Opening the Export menu". An action with a caption shows it; an action without one clears it; reads leave it. A `batch` takes one caption, and each step may set its own from that step on. Captions are trimmed to one line of at most 80 characters and end with the turn. Browser actions (`browser_click`, `browser_type`, `browser_press_key`, `browser_scroll`, `browser_navigate`, `browser_command`) take a caption too; the extension draws the same cursor and caption inside the agent's tab, and hides them from the agent's own screenshots, snapshots and DOM reads.

## Turn end

`POST /turn-ended` uses the same token and origin checks as `/api`. An optional body `{"session_id": "…"}` selects a session; otherwise the `Mcp-Session-Id` header selects the transport's session, and omitting both selects `legacy`. It resets only that session's diff baselines so the next read is full, clears its session app approvals, and releases personal tabs it claimed. Agent-created tabs and the session stay open. It returns `{ok, session_id, released_tabs, cleared_app_approvals}`.

`SecondCursor --turn-ended --session <id>` calls it, always exits 0, and ignores stdin. The CLI without `--session`, the `scripts/cursor-hooks.json` sample, and the hook merged by `install-mcp --client cursor --with-hook` target only `legacy`; they cannot infer or clear an automatically issued MCP session. Hosts using automatic sessions should send their header or pass the ID explicitly. Stdio EOF closes that proxy's transport session only.

## Finding elements

`find_elements` searches the session's latest observation of a window instead of reading the window again: `{window_id | app, text?, role?, limit?}`, with at least one of `text` and `role`. `text` matches each element's label, value and description, ignoring case: exact matches rank first, then prefixes, then substrings; within a rank, indexed elements come before plain text, then outline order. `role` is an AX role with or without the `AX` prefix (`AXButton`, `button`). The search covers every element the latest read walked (up to 2500, or three times `max_elements`), including elements a truncated outline left out; those get indexes like any other and stay actionable while they exist. The result is `{matches, total, observation_id, window_id}`: up to `limit` (default 20, 1–100) outline lines with `[index]` and frames, the number of matches before the limit, and the read that was searched. `hint` asks to refine the query when `total` exceeds the limit, or to read again when nothing matched. An action's observation counts as a read, so a search after an action sees its result; after a change without one (`observe: "none"`, another client, time passing), call `get_window_state` first. A window the session has not observed yet is read once (`read_window: true`), and that read becomes the session's observation and the baseline of its next diff. By `app`, it searches the app window the session observed last, or the app's main window when there is none. It is a read: the same gates as `get_window_state`, and nothing is logged.

## act and the compact tool surface

`act` is `batch` under another name: the same schema, arguments, results, errors and action log lines (logged as `batch`). Its description presents it as the way to act, with one step or many. `toolSurface` in the config chooses what `tools/list` advertises on `/mcp` and `/api`: the default (or `"full"`) lists every tool except `act`, including `browser_repl`; `"discrete"` is the default without `browser_repl`; `"compact"` lists ten tools for clients with tool-count limits or weaker models: `status`, `list_windows`, `launch_app`, `get_window_state`, `find_elements`, `act`, `operation_status`, `browser_open`, `browser_snapshot` and `browser_repl`; `"repl"` lists only `browser_repl` and sends no server instructions. Every surface but `"repl"` advertises the read-only `operation_status` tool and its required `operation_id`, so a model can reconcile an uncertain action using the ID in its result or error before observing the target and deciding what to do next. Session ownership and operation cancellation remain host-managed: no surface lists `session`, `bind_target`, or `cancel_operation`. The `session_id`, action `operation_id`, `observation_id`, and host `timeout_ms` arguments remain hidden (`wait_for` and `browser_repl` still list the `timeout_ms` that bounds their own wait). Models once offered `browser_repl` next to the discrete browser tools, with nothing saying which to use, mixed the two and ran slower than with either alone; the descriptions now give `browser_repl` multi-step web flows and the discrete tools single steps, and `"discrete"` keeps the old list for comparison (`e2e/jev_triage.py` arms `agent:M` and `both:M`). `python3 e2e/benchmarks/tool_surface.py` reports each preset's tool count and schema bytes. Every tool stays callable either way, so existing clients and the SDK keep working. The value is read at startup; anything else counts as the default. `python3 e2e/agent_smoke.py --run --config toolSurface=compact` measures a model on the compact surface.

## Browser REPL

`browser_repl` is listed on every surface but `"discrete"` (see above) and callable on any surface. It runs `code` in a persistent JavaScriptCore context for each session/browser-instance pair and returns as text what it printed followed by the value of its last expression. An omitted `browser_id` requires exactly one connected browser, which is then pinned for that call. Switching browser instances selects a separate context; returning to the original instance restores its context. Top-level `await` works, and top-level `const`, `let`, `var`, `class` and function declarations persist between calls and can be declared again. `page` is a Playwright-compatible page on a background Chrome tab the session owns (opened on first use), and `context` is its browser context (`newPage()`, `pages()`). Locators follow Playwright: `getByRole`, `getByText`, `getByLabel`, `getByPlaceholder`, `getByAltText`, `getByTitle`, `getByTestId`, CSS, XPath and `text=` selectors, chaining, `filter({ hasText, hasNotText, has, hasNot, visible })`, `nth`/`first`/`last`, `and`/`or`; names and texts match case-insensitively as substrings unless `exact: true`, and RegExps work. Actions wait up to 5 s (`page.setDefaultTimeout`, or `{ timeout }`) for exactly one attached, visible, enabled element that receives the click; more than one match fails at once as a strict mode violation. `page.snapshot()` returns the outline `browser_snapshot` gives, and its `[e123]` refs work as `page.locator('aria-ref=e123')`. A dialog an action opens is dismissed, with a `[system]` line, unless `page.on('dialog')` answers it. A screenshot returned as the cell's value comes back as an image.

`locator.hover({modifiers, timeout, force})` and `page.mouse.move(x, y)` send a browser pointer move through CDP. Mouse-move `steps`, `locator.dragTo`, and `mouse.down`/`mouse.up` remain unsupported and throw. Use the extended `drag` operation for a coordinate-based left-button pointer drag; it does not synthesize an HTML5 `DataTransfer` drag.

There is no `page.evaluate`, network, filesystem, module loading or timer other than `page.waitForTimeout`: the context holds JavaScript's builtins, `page`, `context` and `console`, and its browser calls are limited to the operations above, pinned to the session. Output is capped at 40,000 characters. A script that runs 5 s without yielding, runs past the call's deadline (`timeout_ms`, 55 s by default and at most, under clients' 60 s tool timeouts), or grows the process by more than 1 GB in one call is stopped; after the memory stop the context starts over. A client that closes its connection or sends `notifications/cancelled` for the call ends it at once. Calls within each context run one at a time, and no script runs between them. Unsupported options and extra arguments throw instead of being ignored. Clicks and key presses wait for a page load they start, and every call reports the tab's URL to `page.url()`. Contexts last across turn ends, like the agent's tabs; closing the session closes every browser context belonging to it. Each call is logged with its code, and each navigation with its URL. Failure modes and their checks are in `e2e/repl.py`.

## Native editing

- `select_text`: element index, exact text, optional prefix/suffix, and selection_type `text`, `cursor_before`, or `cursor_after`. Ambiguous matches fail.
- `paste`: `text`, `html`, or `md`. Markdown inserts source text. Paste waits up to one second for the exact expected value/selection insertion, then restores the previous in-memory clipboard only if it still owns the clipboard. A copy the user makes meanwhile survives. If insertion cannot be confirmed or the attempt is interrupted, the previous clipboard is not restored because a delayed handler may still consume the paste content; the result reports uncertainty. Unless the user has copied something else, the paste content remains on the clipboard. The saved previous clipboard is kept only in memory.
- `inspect_element`: `offset` and `length` recover truncated text; the response includes `total_length`, `has_more`, selection, editability, and available actions.
- `perform_action`: choose an action listed in the observation (custom actions by the name shown).

## Extended browser interface

Use `browser_instances` to discover instance IDs and supply `browser_id` when more than one profile is connected. Agent-created tabs work without prompts. `browser_command` takes `operation`, `tab_id`, `browser_id`, session fields, and an `arguments` object for operation-specific fields (flat arguments still work). `operation: capabilities` returns argument help, the CDP allowlist, and which operations need approval.

Locators use one or more of `selector`, `role`/`name`, `label`, `text`, `placeholder`, `test_id`; matching is exact unless `exact:false`. `nth` selects an explicit match. `frame` is a selector or an array for nested frames, including cross-origin frames. Ambiguous matches fail.

| Operations | Arguments / result |
|---|---|
| capabilities | Operations, argument help, CDP allowlist, approval requirements |
| user_tabs, claim, release | Discover personal tabs and claim one (both ask); release without closing |
| retain | mode: ephemeral, deliverable, handoff; retained tabs survive session cleanup |
| dom_snapshot, inspect | Structured DOM state; inspect supports offset/length and returns attributes and bounds |
| click | locator or x/y; button, count, modifiers |
| hover | locator or x/y; optional modifiers; CDP mouse move |
| fill, type, paste | text; paste format text/md/html; HTML requires a locator |
| select_text | text, prefix/suffix, selection_type |
| check, select_option | checked boolean; option value |
| perform_action | locator and an advertised action: focus, scroll_into_view, expand/collapse, increment/decrement |
| press_key, scroll | keys; direction/amount and optional locator |
| drag | from_x/from_y/to_x/to_y; left-button pointer drag only; modifiers, button, and count are refused |
| back, forward, reload | Browser navigation |
| wait | url substring, locator/state, or event download/filechooser/navigation; bounded timeout_ms |
| dialog | Omit accept to inspect; accept boolean and optional prompt_text to answer |
| upload | Absolute regular-file paths; locator or an intercepted chooser; asks first |
| screenshot | full_page or clip; PNG plus dimensions, scale and document-coordinate origin |
| viewport | width/height, or reset:true |
| logs, history | Console entries; history asks first, with query/from/to/limit (Unix milliseconds) |
| export | text/html/md/pdf; Google Workspace xlsx/csv/docx/pptx; youtube_transcript on watch pages |
| assets | List observed resources; action:bundle and asset_ids return selected bodies |
| clipboard | action read/write, text; asks first; the page origin must allow clipboard access |
| cdp | Asks first; only Page.getLayoutMetrics, Page.getNavigationHistory, DOM.getDocument and Accessibility.getFullAXTree |
| batch | Array of extended operation arguments, each flat or nested under `arguments` like the call itself; returns results and a final DOM observation |

A dialog-triggering action returns the observed dialog instead of waiting for the click to complete. File choosers are intercepted, so files can be assigned without moving the system cursor.

`fill`, `check`, and `select_option` read the control's value, checked state, or selected values after its synchronous handlers run. Their outcome includes the verification kind and expected/actual values, with secret field values redacted. This verifies the requested control state, including one that was already satisfied; it does not prove a form was submitted or saved by a server. An uncertain property result throws a visible “not verified” error in the REPL so later script steps cannot silently treat it as success. Other browser input reports dispatch rather than inferring success from a following snapshot. Pointer drags depend on the page accepting pointer input and do not promise native file dragging, cross-app dragging, or HTML5 drag-and-drop payloads.

Password and payment card fields (by type, autocomplete, or a label such as "Card number") read `value="[redacted]"` in `browser_snapshot` and action observations, and `[redacted]` in `dom_snapshot`, `inspect`, `fill`'s result and HTML export. `select_text` refuses them, since how often a text matches would reveal the value a guess at a time. Screenshots show what the page shows. The approval-gated `cdp` operation returns what Chrome reports and is outside this redaction.

A tab or popup window that an agent tab opens (a `target=_blank` link, `window.open`) becomes an agent tab of the same session. If Chrome made it the active tab of the user's window, the tab the user was viewing is brought back. Chrome still shows the new tab for a few frames first, and nothing can stop a popup window from taking focus. Things the model did not ask about are queued per session and reported on the next result of `browser_open`, `browser_navigate`, `browser_snapshot`, `browser_click`, `browser_type`, `browser_press_key`, `browser_scroll`, `browser_close` or `browser_command`, as `events: ["[system] popup opened: tab 12 https://… (from tab 11)", …]`. The events are a popup opened, an agent tab closed by the page or the user, a download started, finished or canceled, and a dialog opened or closed. In a `batch`, each step's result carries its own events. Google Workspace exports need a signed-in document; YouTube transcripts need captions. These service-specific paths are not covered by the local fixture suites.

## JavaScript SDK

```js
import { SecondCursor } from './sdk/index.mjs';
const sc = await SecondCursor.local();
try {
  const notes = await sc.app('TextEdit');
  const area = notes.observation.elements.find((e) => e.role === 'AXTextArea').index;
  const { observation } = await notes.batch([
    { tool: 'select_text', element_index: area, text: 'draft', selection_type: 'cursor_after' },
    { tool: 'type_text', element_index: area, text: ' (reviewed)' },
  ], { expect: { text: 'draft (reviewed)' } });
  console.log(observation.tree);
} finally { await sc.close(); }
```

`SecondCursor.local()` reads the config (respecting `SC_HOME`) and creates a session. A directly constructed client obtains a session on its first call. `transport: 'mcp'` exercises `/mcp` instead of `/api` and maintains the MCP session header. `App` and `Tab` handles adopt returned observations and send their snapshot ID on later actions; handles for the same target share the latest observation. `observe()` requests structured elements, and `app()` refuses an ambiguous multi-window selection. Pause, takeover, resume, and a missing or lost action observation invalidate cached target observations; wrappers refuse the next mutation with `STALE_OBSERVATION` until `observe()` grounds it again. `call()` exposes every tool.

`SecondCursorError` carries `code`, `operationId`, `sessionId`, `tool`, `outcomeUncertain`, `recovery`, and any available HTTP `status` or parsed `result`. `call(tool, args, {signal, timeoutMs})` supports aborts and a client timeout (65 seconds by default, separate from the server's `timeout_ms`). An abort or lost response can leave input already dispatched; the SDK does not automatically retry mutations. When `error.recovery` is `operation_status`, use `await sc.reconcile(error)` or `await sc.reconcile(operationId)` to read the operation state, then observe the target before choosing another action. A supplied different session ID is refused. The other recovery values are `task_state`, `session_state`, and `target_state`; those controls are not journaled, so `reconcile(error)` throws `UNTRACKED_OPERATION` with guidance. For a task-control error, use `task().get()` to inspect the current state. An `onResult` callback failure preserves the action result and reports `outcomeUncertain: false`.

`createTask({title, client_name})`, `task(id?)`, and `bindTask(id)` return a `Task` handle with `get`, `update`, `pause`, `takeover`, `resume`, and `cancel`; `tasks()` lists task snapshots; pass `{include_finished: true}` to include finished work. Use `update({status: 'thinking'})` for host progress and `update({status: 'completed'})` only after the host has finished its work. `Tab.hover([x, y])` and `Locator.hover()` expose browser hover. The SDK package includes TypeScript declarations.

`sdk/agent.mjs` is an optional model-independent loop; its adapter owns provider-specific encoding and its approval hook belongs to the host. For multi-step flows with branching, a short Node script using the SDK is often better than many separate tool calls; see `.cursor/skills/second-cursor/SKILL.md`.

For an opt-in resumable agent, import `runAgent` and `fileCheckpointStore` from `@second-cursor/client/agent` (or `./sdk/agent.mjs`). Give each workflow a stable ID, goal, checkpoint path, and target identities. Construct an unconnected `SecondCursor` client so the loop can restore the checkpoint's original session before connecting; `SecondCursor.local()` has already connected and may create a different session.

```js
const result = await runAgent({
  adapter, // Your model adapter: next({ task, tools, history, progress }).
  client: new SecondCursor({ url, token }),
  task: 'Reconcile the three specified invoice drafts and verify each submission.',
  workflow: {
    id: 'invoice-reconciliation-2026-10-04',
    store: fileCheckpointStore(checkpointPath),
    targets: [{ browserId, tabId }], // Or { windowId } for a native target.
  },
  onApproval,
});
```

The loop saves ordered history, adapter-supplied `progress`, and an operation ID before dispatch. After a process restart it reconciles the pending operation in the original session, discards unexecuted calls from the interrupted turn, and reads the targets again before asking the model to continue. A completed checkpoint returns its saved result without another model call. Unknown, expired, or uncertain outcomes return `stopped: 'recovery_required'`; paused, cancelled, and interrupted runtime tasks require the host to handle their lifecycle. The loop never automatically resumes a task or repeats an uncertain mutation. Keep the original session open while work remains resumable.

File checkpoints use atomic writes, mode 0600, and one process owner at a time. They deliberately contain the goal, tool arguments/results, and potentially screenshots, so choose a private path and delete them according to your retention policy. Runtime bearer credentials are excluded; provider credentials belong in the adapter's configuration, never in its returned history or progress. Ordinary `runAgent` calls without `workflow` retain the in-memory behavior. See [workflow acceptance](acceptance-workflow-recovery.md) and [the interrupted invoice test](acceptance-invoice-workflow.md).

The store automatically recovers a lock left by a dead local process. A crash during that lock-recovery step can leave a `.lock.recover` marker and deliberately block further runs; remove that marker only after confirming that no workflow runner is still alive.

## Validation

Desktop and browser suites use a disposable test instance: the harness starts the installed bundle with its own `SC_HOME`, port, token, and config (`approvals: "allow"`, `appApproval: "off"`), without changing your configuration or restarting your app. Pass `--installed` to target your own instance instead, `SC_E2E_APP=<bundle>` to test another build, `--browser` to force the isolated headless browser, and `--approvals` for interactive prompt scenarios (they show real dialogs and never click them). `task_ui.py --ui` deliberately opens the disposable task/setup panels; `native_safety.py --takeover` includes a foreground fixture. Transport and SDK checks also use isolated local servers without desktop input.

```sh
python3 e2e/run.py        # core regressions
python3 e2e/policy.py     # approvals (deny mode, no UI), turn end, action log
python3 e2e/parity.py     # sessions, editing, browser
python3 e2e/review.py     # observation size, leases, bookkeeping (add --short-retention for expiry)
python3 e2e/instance.py   # test-instance isolation
python3 e2e/setup.py      # stdio proxy, doctor, turn end, install-mcp (--ui adds the onboarding panel)
python3 e2e/cursor.py     # arrow and menu-bar presence, drawn on the agent display (cursorOnAgentDisplay)
python3 e2e/clicks.py     # every pixel click, double-click and drag acts exactly once
python3 e2e/focus.py --takeover   # focus safety; takes focus and covers the screen while it runs
python3 e2e/latency.py    # per-call timings, written to latency.json
python3 e2e/expect.py     # expect postconditions, wait_for, notification-driven settling
python3 e2e/find.py       # find_elements, act, the compact tool surface
python3 e2e/repl.py       # browser_repl: persistence, limits, sandbox, Playwright locators
python3 e2e/tasks.py      # task lifecycle, takeover/resume, interrupted recovery
python3 e2e/transport_recovery.py # automatic MCP ownership and operation journal recovery
python3 e2e/native_safety.py # human-input gates, capabilities, native layout guards
python3 e2e/browser_reliability.py # browser freshness, hover, form state and settling
python3 e2e/release_setup.py # bundle portability, setup diagnostics and browser self-test
python3 e2e/task_ui.py --ui # rendered task and setup controls; intentionally opens panels
python3 e2e/ocr.py        # text recognition; a small custom-drawn fixture window on the agent display, timings in ocr-timings.json
python3 e2e/agent_smoke.py --run   # a real Cursor agent drives the tools (costs model usage)
```

Failure cases are recorded in the acceptance documents for [task lifecycle](acceptance-tasks.md), [native safety](acceptance-native-safety.md), [browser reliability](acceptance-browser.md), [transport recovery](acceptance-transport.md), [SDK behavior](acceptance-sdk.md), and the earlier [parity](parity-acceptance.md) and [review](review-acceptance.md) work. Reports, transcripts, screenshots, and exported files are written to `e2e/artifacts/<run-id>/`.

`python3 e2e/best_in_class.py gate --profile quiet` runs unattended checks serially and preserves skipped or inconclusive evidence as incomplete. The `tasks --rounds 3` mode independently judges complete workflows with fresh fixtures; its built-in adapter is deterministic, not a model benchmark. The [release evidence contract](best-in-class-acceptance.md) defines the attended gate, exact-build evidence, and requirements for a comparative claim.
